# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An n8n community node package (`n8n-nodes-zabbix`) for the **Zabbix 7.4 JSON-RPC API**. Built programmatically because the Zabbix API is a single JSON-RPC 2.0 endpoint (`/api_jsonrpc.php`) — every call POSTs `{jsonrpc, method, params, id}` with the method name (e.g. `host.get`) in the body, which n8n's declarative `routing` can't express.

## Zabbix node architecture (`nodes/Zabbix/`)

- Two node classes: `Zabbix.node.ts` (action node) and `ZabbixTrigger.node.ts` (polling trigger — `poll()` pages `event.get` forward from a `lastEventId` watermark in `getWorkflowStaticData('node')` with `eventid_from` ASC, so bursts aren't truncated and each event fires once; first poll only bootstraps the watermark; manual runs return the latest match without moving it). Recovery events carry `severity: 0` and `event.get` can't filter on `r_eventid`, so "Problem Resolved" filters on `relatedObject.priority` and finds the original problem by `objectids` + matching `r_eventid`. Both are registered in `package.json` `n8n.nodes`.
- `helpers/resourceFactory.ts` provides three builders: `createCrudResource` (Create/Get Many/Update/Delete + auto "Additional Parameters (JSON)" escape hatch, `jsonWriteKeys`/`relationWriteKeys` transforms), `createGetOnlyResource` (single Get Many for read-only objects), `createConfigResource` (Get/Update for id-less singletons like settings). Simple objects are ~30-line configs; objects with extra verbs (host mass ops, event acknowledge, history push/clear, script execute, configuration import/export, usermacro global variants) are hand-written modules.
- `Zabbix.node.ts` — the `INodeType`. Holds the full `INodeTypeDescription` (icon, resource dropdown from `actions/index.ts` `resourceOptions`, aggregated `properties`) and `execute()`, which loops input items and dispatches to the selected resource module's handler. The community-nodes linter requires the description **and** the `continueOnFail` try/catch loop to live in this file (don't move them to separate `router.ts`/`versionDescription.ts` — that trips `icon-validation`, `require-continue-on-fail`, and `node-filename-against-convention`).
- `actions/index.ts` — the resource registry: `resources` map (`name → module`) and `resourceOptions` dropdown. Add a resource by creating `actions/<name>/index.ts` and registering it here.
- `actions/<resource>/index.ts` — each exports `description: INodeProperties[]` (operation dropdown + fields gated by `displayOptions.show`) and `handlers: Record<operation, (this, itemIndex) => INodeExecutionData[]>`. See `actions/host/` as the reference implementation and `actions/customApiCall/` for the raw-method escape hatch.
- `transport/index.ts` — `zabbixApiRequest(method, params)`: the one primitive. POSTs JSON-RPC, throws `NodeApiError` carrying Zabbix `error.data` on failure, else returns `result`.
- `descriptions/getCommon.description.ts` — `getCommonDescription(resource)` (reusable `output`/`filter`/`search`/Options fields for every `.get`) + `buildCommonGetParams()` reader. Reuse these in every Get Many operation.
- `helpers/utils.ts` — `wrapZabbixResult`, `parseJsonParameter`, `removeEmpty`, `idListToObjects` (comma IDs → `[{groupid}]`), `toIdArray`. `helpers/interfaces.ts` — `IZabbixResourceModule`, handler types.
- `methods/loadOptions.ts` — dynamic dropdown loaders (host groups, templates), wired into `node.methods.loadOptions`.

Delivery is in waves (see `~/.claude/plans/indexed-waddling-stream.md`): wave 1 = framework + Host + Custom API Call (done); waves 2–4 add the remaining ~45 objects following the same recipe.

## Convention notes / gotchas

- `@n8n/node-cli` is pinned to a caret range (not `*`) so a new CLI major can't silently introduce a lint rule that breaks a clean `npm install`. eslint is pinned to `9.29.0` to match `@n8n/node-cli`'s peer requirement — bumping it breaks `npm run lint` with a missing `@eslint/js`. `n8n-workflow` is a devDependency (for build/types) and a peerDependency (not bundled — required for n8n verification).
- Combine `n8n-workflow` imports into a single statement per file (`import { X, type Y }`) — the linter's `import-x/no-duplicates` flags separate `import` + `import type` from the same module.
- Boolean field descriptions must start with "Whether"; resource/operation option lists should be alphabetical by label.
- In factory `writeFields`, the literal marker `(required on create)` in a field's description is what promotes it to a top-level required field on Create (and an optional "leave empty to keep unchanged" field on Update); fields without the marker land in the optional "Additional Fields" collection. A marked field with a non-blank default (number/options) can't be top-level on Update — n8n would always send its default — so the factory puts its Update copy inside the collection instead. Action labels are generated by `noun()`/`article()`/`plural()` in `resourceFactory.ts`, which preserve all-caps acronyms (SLA→"an SLA", LLD, MFA) and treat "user" as "a user" — don't hand-write articles in factory-built resources.
- Never name a top-level `const module` in a resource file — it shadows CommonJS's `module` wrapper var, and the compiled CJS then fails to load (Node falls back to ESM and the extensionless `require` throws "Cannot find module"). Use `resourceModule`. Factory-built resources follow `createCrudResource`/`createGetOnlyResource` in `helpers/resourceFactory.ts`; the smoke test in the repo root loads `dist` and lists each resource's handlers.

## Commands

- `npm run dev` — build in watch mode and launch a local n8n with the nodes loaded + hot reload (http://localhost:5678). Primary dev loop.
- `npm run build` — compile TypeScript to `dist/` (via `n8n-node build`). `dist/` is what gets published.
- `npm run lint` / `npm run lint:fix` — n8n node linter (enforces community-node conventions, not just style).
- `npm run release` — lint, build, version bump, changelog, tag, push (triggers npm publish via GitHub Actions).

- `npm run test:smoke` — all 223 operations against a mocked transport (asserts each builds a valid JSON-RPC request). Run after `npm run build`; it loads `dist/`.
- `npm run test:e2e` / `test:e2e:full` / `test:e2e:trigger` / `test:e2e:compat` — live suites against a disposable Zabbix (`docker compose -f test/docker-compose.zabbix.yml up -d`; `ZABBIX_TOKEN=$(npm run -s test:token -- http://127.0.0.1:8089)`). Creates and deletes real objects — never point at production. **Always pass `ZABBIX_URL` (and `ZABBIX_TOKEN`) explicitly** — values inherited from the shell may point at a real Zabbix (the suites' localhost guard aborts, but don't rely on it). `ZABBIX_TAG=alpine-trunk ZABBIX_WEB_PORT=8090 ZABBIX_SERVER_PORT=10152 docker compose -p zabbix-node-test-trunk …` runs the 8.0 dev branch side by side; `.github/workflows/e2e.yml` runs all four suites on 7.4 + trunk.

Version handling lives in `transport/index.ts` and is verified live on 6.0, 6.4, 7.0, 7.2, 7.4 and 8.0-trunk: `zabbixVersion()` (cached per URL) drives auth placement (`auth` in the body before 6.4, Bearer header from 6.4), `adaptRequest`/`adaptResult` (pre-7.0 proxy fields `host`/`status`/`interface` and host `proxy_hostid`; pre-6.2 `selectGroups`, import rules `groups`, `hostgroup.massupdate` requiring `templates`), and the error translation ("X is not available on Zabbix <version>", "object not found, or no permission"). The e2e suites count "not available" as skipped (⏭), not failed. Read-only credentials are enforced there too (`isReadMethod`). The credential test is `zabbixCredentialTest` (`testedBy` on both nodes) because it must share this logic; it only gets the legacy `helpers.request`, hence the scoped eslint-disable.

Composite NOC operations: `problem → getContext` (`problemContext()` in `actions/problem`) and `host → getHealth` (`hostHealth()` in `actions/host`); shared formatting (severity names, links, local time, Simplify, `attachHosts` because `problem.get` has no `selectHosts`) is in `helpers/eventFormat.ts`. `createGetOnlyResource` takes `extraFields`/`extendParams`/`transformResult` hooks for this.

Zabbix 8.0 differences (verified on trunk, reports `8.0.0`): the four `*.massupdate` methods are gone — `transport/index.ts` detects the major version (cached per URL, invalidated on "Method not found") and rebuilds them (`REMOVED_IN_8`); `history.push` requires the item's `trapper_hosts` to allow the frontend IP (e2e items set `0.0.0.0/0`); new objects `apm*`, `ceprule`, `device`, `serverinfo` are deliberately not typed resources until 8.0 GA.

Requires Node.js v22+ (declared in `package.json` `engines`). Two live-API gotchas the e2e suite encodes: `apiinfo.version` must be called WITHOUT an Authorization header (transport special-cases it); `script.getscriptsbyhosts`/`byevents` take `{hostid: <number>}` one at a time (handlers loop and merge); `history.push` returns "success" with per-value `data[].error` entries that the handler surfaces as a thrown error.

Credential: `credentials/ZabbixTokenApi.credentials.ts` (internal name kept as `zabbixTokenApi` so saved credentials survive; display name "Zabbix API") — `authentication` API token or username/password (`user.login`, session cached and renewed once on expiry), `readOnly`, `extraHeaders` (JSON, masked — the lint warning about it is expected), `ignoreSslIssues`. No `test` block: the nodes' `testedBy` runs the transport. The transport strips a pasted `/api_jsonrpc.php` from the URL (`zabbixBaseUrl`). Node icon lives in `icons/` and is referenced via `icon: { light: 'file:../../icons/zabbix.svg', dark: ... }`; each node also has a sibling `Zabbix.node.json` codex file.

## Conventions

- TypeScript is strict (`noUnusedLocals`, `noImplicitAny`, `strictNullChecks`). Import types from `n8n-workflow` — verified/community nodes must avoid external runtime deps.
- Set `usableAsTool: true` on the **action node only** (`Zabbix.node.ts`), so it is usable as an AI-agent tool.
  Never set it on `ZabbixTrigger.node.ts` — trigger nodes can't be invoked as tools, and `@n8n/node-cli` ≥ 0.45
  fails `npm run lint` on it (`@n8n/community-nodes/node-usable-as-tool`).
- Registered node/credential entry points in `package.json` `n8n.{nodes,credentials}` point at compiled `dist/...js` paths — keep them in sync when adding files.
